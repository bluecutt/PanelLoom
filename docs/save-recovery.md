# Saving, recovery and asynchronous work

Save and save-as use the same atomic ProjectStore as CLI, checking the saved destination hash. External edits produce Conflict; save-as to a new file is the safe alternative. Undo/redo after save-as rebase every history snapshot to the new project directory, preserving actual source assets.

Normal state lives in the current user's LocalAppData/ComicEditor.Native/0.1. `--portable-data` explicitly uses Data beside the application. An unwritable chosen location stops startup; there is no silent fallback. Settings and logs are separate from projects. Recovery snapshots are written at most once per changed revision on the two-second timer while dirty; they contain project JSON/path/hash, never embedded image data, and never overwrite the formal project. The Recovery dialog loads a snapshot as unsaved work. Corrupt recovery files are retained rather than deleted.

Previews render off the UI thread with one in-flight frame plus one latest state, sampled about every33ms. Same-interaction input does not cancel a usable frame; document/asset/interaction epoch changes reject stale completions. Esc restores the baseline and gesture completion requests an exact terminal frame. Bounded preview leases release source streams and do not lock original files. Export reads a fixed project snapshot through the strict original-source renderer with its memory budget and atomic PNG commit. Cancellation is cooperative and produces no newly committed partial PNG; existing outputs remain unchanged. Formal source fingerprints are re-read, not served by the preview cache. A modal dialog, pending property entry, drag or export will be a busy boundary for the live Agent session.
